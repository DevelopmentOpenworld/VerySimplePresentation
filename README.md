# VerySimplePresentation

Сервис собирает презентацию по образцу. Пользователь загружает презентацию-образец (PPTX или POTX, ранее сервису неизвестную), описывает задачу и, по желанию, прикладывает материалы по теме. Сервис разбирает образец как набор правил, пишет содержание и выдаёт **три варианта вёрстки одного содержания** в стиле образца. Каждый вариант — PPTX на мастерах и макетах самого образца (нативные объекты, текст в плейсхолдерах, нативные графики со встроенной книгой Excel, текст выступления в заметках), самостоятельный HTML и PDF, с находками аудита. Пользователь отмечает находки, которые нужно исправить, и получает новую ревизию.

Задача на странице задаётся простыми полями: «О чём презентация» (от одного предложения до текста в 200 000 знаков), назначение (фича, продукт, проект, инициатива, другое), число слайдов (по умолчанию 10–15, по просьбе от 3 до 15), аудитория и длительность выступления. Материалы: txt, md, csv, json, docx, pptx/potx с заметками, pdf с текстовым слоем, zip, шрифты. Через API можно передать и структурированный бриф — готовый набор фактов (схема `vsp.brief/1`, пример — `examples/brief-pilot.json`).

Ход работы страница показывает по событиям сервера: шаг загорается, когда сервер его начал, у каждого шага — измеренное время и итог, у каждого запроса к модели — время ответа.

## Три варианта

| Вариант | Код | Как подаются факты слайда |
|---|---|---|
| Вариант 1 · колонки | `columns` | факты рядом, для сравнения: ряд карточек образца или макет с двумя колонками; слайд со сравнимыми числами — нативный график рядом с фактами |
| Вариант 2 · блоки образца | `split` | каждый факт — отдельный блок на композиции собственного слайда-образца; слайд с числами — карточки с крупным ключевым числом |
| Вариант 3 · иллюстрации образца | `sequence` | для каждого текстового слайда — композиция образца, которая несёт картинку самого шаблона (вырезанные иллюстрации слайдов-образцов, наборы карточек с картинками); слайд с шагами — ряд карточек со стрелками |

Во всех трёх одинаковы факты, их тексты, заголовки-выводы, порядок и число слайдов; различаются только средства самого образца. Подробно — [VARIANT_AXIS](docs/VARIANT_AXIS.md).

## Запуск в Docker (Linux-сервер)

Образ собирает всё сам: Python 3.12, Node.js 20, Playwright с Chromium, открытые шрифты-замены из `profiles/mvp/fonts.json` (закреплённый коммит `google/fonts`, каждый файл сверяется с ним).

```bash
docker build -t verysimplepresentation .
docker volume create vsp-fonts
# один раз: полный набор Google Fonts без китайских, японских и корейских шрифтов (1805 семейств, около 859 МБ) в отдельный том
docker run --rm -v vsp-fonts:/fonts verysimplepresentation python -X utf8 -B scripts/fetch_fonts.py fetch catalog --dest /fonts
docker run -p 8770:8770 -e VSP_ACCESS_KEY -e VSP_LLM_API_KEY \
  -v vsp-runs:/app/var/generator -v vsp-fonts:/fonts verysimplepresentation
```

Ключи берутся из переменных окружения того, кто запускает, — в строке запуска их значений нет. Настройки контейнера — `config.docker.json`. Проверьте, что в нём задано `"provider": "openrouter"`: тогда сервис вызывает модель с ключом `VSP_LLM_API_KEY`. При `null` действует поставщик по умолчанию из `profiles/llm/models.json` — `replay` (записанные ответы); записанных ответов в репозитории нет, поэтому все вызовы модели пойдут запасным путём и содержание будет взято только из текста задачи. В `origins` укажите адреса, по которым пользователи открывают сервис, например адрес вида `presentations.example.ru` со схемой https: запросы с других адресов сервер отвергает.

Шрифты Microsoft (Verdana, Trebuchet MS, Arial Black, Georgia и другие) ставятся, только если вы принимаете их лицензию: `docker build --build-arg MS_CORE_FONTS_EULA=accept -t verysimplepresentation .`

Вход по секретной ссылке: при заданной переменной `VSP_ACCESS_KEY` (не короче 24 знаков) сервис отвечает только браузеру, который один раз открыл адрес сервиса с параметром `?key=<ключ>`; переход ставит cookie (HttpOnly, SameSite=Strict) и убирает ключ из адресной строки; остальные запросы получают 403.

## Запуск локально

1. **Python 3.12.** Продукт использует только стандартную библиотеку.
2. **Node.js 20.19+** и Chromium — для обязательной проверки отрисовки и печати PDF; `npm install` ставит также pdf.js (`pdfjs-dist`, Apache-2.0), которым сервис читает PDF из материалов:

   ```bash
   cd apps/generator
   npm install
   npx playwright install chromium
   ```

3. **Настройки:** скопируйте `config.example.json` в `config.json` — адрес, порт, каталог результатов, поставщик модели (`"openrouter"`), пути Node, каталоги шрифтов, разрешённые адреса.
4. **Открытые шрифты-замены** (метрически совместимые замены шрифтов Microsoft, 25 файлов, 7,6 МБ; [FONTS](docs/FONTS.md)):

   ```bash
   python -X utf8 -B scripts/fetch_fonts.py fetch substitutes
   ```

5. **Запуск:**

   ```bash
   python -X utf8 -B apps/generator/server.py --config config.json
   ```

   Интерфейс — `http://127.0.0.1:8770/`. Образец PPTX загружается на странице; образца по умолчанию нет.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `VSP_LLM_API_KEY` | ключ OpenRouter для модели (поставщик `openrouter`); в файлы и журналы не попадает |
| `VSP_ACCESS_KEY` | ключ секретной ссылки доступа; без него сервис открыт всем, кто знает адрес |
| `VSP_NODE_EXECUTABLE`, `VSP_NODE_MODULES` | где Node.js и модули Playwright, если не в `PATH` и не в `apps/generator/node_modules` (или ключи `node`, `node_modules` файла настроек) |
| `VSP_FONT_DIRS` | каталоги шрифтов сервера с описью `index.json` вместо `var/fonts` (или ключ `font_dirs` файла настроек) |

## Версии

Состав продукта (код, промпты, схемы ответов, профили, офлайн-шрифты) запечатан по SHA-256 в `profiles/mvp/release.json`; сервер при запуске и перед каждой генерацией сверяет файлы с ним. Версии промптов, схем и агентов записываются в `run.json` каждого запуска и отдаются `GET /api/versions`. Промпты и параметры агентов лежат отдельными файлами: `prompts/<агент>/v<N>.md`, `schemas/`, `profiles/llm/agents.json`, `profiles/llm/models.json`. Утилита `apps/generator/manage.py`: `seal` — запечатать состав после правки, `activate <id>` — вернуть зарегистрированный состав.

## Модель

Qwen3.8-27B (открытые веса, Apache 2.0) через OpenRouter с закреплёнными провайдерами Parasail → CoreWeave → DeepInfra, без рассуждения, с ответом строго по JSON-схеме агента; медленный вызов повторяется у следующего провайдера. Подробно — [MODELS](docs/MODELS.md).

Измерено: на 15 колодах сторонних шаблонов колода из трёх вариантов — 51–115 с и около $0,03; в строгом режиме ответа — 1 отказ модели из 401 вызова.

## Ограничения

- **Генерация изображений (text-to-image) не реализована.** Третий вариант использует только картинки самого шаблона.
- **Разбор образца ограничен:** сложные заливки, SmartArt, EMF и декор макетов из групп фигур предпросмотр, HTML и PDF рисуют приближённо или не рисуют; в PPTX их рисует PowerPoint, потому что экспорт идёт на самом образце. SmartArt сервис не создаёт: схемы и процессы строятся нативными фигурами. Таблицы — только из структурированного брифа.
- **Память:** шаблон 34,2 МБ с картинками макетов по 4,8 МБ на сервере с пределом памяти контейнера 1 200 МБ не разобран — процесс убит по памяти; для тяжёлых шаблонов нужен сервер с большим объёмом памяти.
- **Время зависит от поставщика модели:** на одних и тех же входах колода шла от 51 до 249 с.
- **Шрифты:** шрифт, которого нет ни в образце, ни среди открытых шрифтов сервера, в предпросмотре, HTML и PDF заменяется, в PPTX остаётся шрифт образца; урезанный встроенный шрифт не содержит знаков, которых не было в исходной презентации. Сервис называет это находками ([FONTS](docs/FONTS.md)).
- **Содержание — только из текста и материалов пользователя.** Короткий запрос дополняется общими утверждениями модели без чисел; каждое помечено находкой «Утверждение дописано сервисом». Сканы PDF без текстового слоя не распознаются.
- **Браузеры:** проверены Chromium, Firefox и WebKit на Windows; Safari на macOS и Яндекс Браузер не проверялись.
