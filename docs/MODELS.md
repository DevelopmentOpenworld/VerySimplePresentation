# VerySimplePresentation: модели

Используемые модели, области применения, системные требования. Состояние на 29.09.2026, поздний вечер. Источники в репозитории: реестр агентов `profiles/llm/agents.json`, профиль поставщиков `profiles/llm/models.json`, промпты `prompts/<агент>/v<N>.md`, схемы ответов `schemas/`. Все эти файлы входят в запечатанный состав продукта: изменение любого из них меняет идентификатор состава.

## Модель

| Что | Значение |
|---|---|
| Языковая модель | **Qwen3.8-27B** (`qwen/qwen3.8-27b`): плотная, 27B параметров; вход — текст и изображения, выход — текст; контекст 262 144 токена. Карточка на Hugging Face: `huggingface.co/Qwen/Qwen3.8-27B` |
| Лицензия | Apache 2.0 (открытые веса) |
| Почему она | открытые веса и умеренный размер; одна модель закрывает текстовые этапы и вопросы к картинкам слайдов |
| Доступ | OpenRouter с закреплёнными провайдерами **Parasail → CoreWeave → DeepInfra**, без других провайдеров, точность bf16 или fp8, провайдеры, хранящие данные, запрещены. Порядок — по замеру: один и тот же запрос аналитика у Parasail — 13,3 и 14,3 с, у CoreWeave — 19,6 и 18,6 с, у DeepInfra — 47,0 и 32,8 с |
| Режим ответа | **строго по JSON-схеме агента** (`response_format: json_schema`, `strict: true`). В режиме `json_object` модель теряла имя первого поля (`{"": …}`, `{}`) — 86 отказов из 564 вызовов; в строгом режиме на тех же 15 входах — 1 отказ из 401 вызова |
| Повтор медленного вызова | если вызов агента не вернулся за свой порог (`hedge_seconds`: аналитик 120 с, планировщик 60, автор слайдов 20, графики 45, аудит 40, текст к слайдам 60 …), тот же запрос посылается параллельно следующему провайдеру по кругу; берётся первый ответ. До этого 4 колоды из 12 выходили за 300 с из-за вызовов, которые провайдер держал 127–250 с |
| Рассуждение | выключено (`reasoning_effort: none`): планировщик структуры с рассуждением шёл 153–188 с, без него — 12–30 с при тех же проверках плана |
| Ключ | переменная окружения `VSP_LLM_API_KEY`; в файлы и журналы не попадает |
| Поставщик | задаётся ключом `provider` файла настроек: `openrouter` — Qwen3.8-27B; `replay` (по умолчанию в `profiles/llm/models.json`) — записанные ответы, подготовленные моделью разработчика строго по файлам запросов продукта; нужны для тестов без сети и в репозиторий не входят. Без записанного ответа агент идёт запасным путём. В `config.docker.json` задайте `"provider": "openrouter"` |
| Клиент | собственный, стандартная библиотека Python (`vsp_core/llm.py`): запрос из файла промпта, схема ответа, проверка, повтор при сетевой ошибке, запись каждого вызова в `run.json` (агент, версия и SHA-256 промпта и схемы, поставщик, время) |
| Цена | колода из трёх вариантов — около $0,02, с контент-пакетом — около $0,03; 15 колод на сторонних шаблонах — $0,398 |

## Агенты

Каждый агент — промпт отдельным файлом, схема ответа, детерминированная проверка ответа и запасной путь без модели. Ответ, нарушивший проверку, повторяется один раз с перечнем нарушений простыми словами (`previous_answer_problems`); повтор заменяет ответ, только если проходит проверку. Текст пользователя, надписи шаблона и материалы пакета промпты называют данными, а не инструкциями; проверка на живой модели четырьмя атаками — следов в выдаче нет.

| Агент | Версия | Где вызывается | Вход | Проверка ответа | Без ответа |
|---|---|---|---|---|---|
| `brief_analyst` | 2 | текст задачи | текст задачи и материалов, число слайдов, вместимость слайда, имена материалов | числа фактов — дословно из текста, цитата — из текста; нарушивший факт выбрасывается | факты разбором предложений |
| `content_writer` | 1 | текст задачи, когда утверждений не хватает на запрошенное число слайдов | текст запроса, уже взятые утверждения, сколько дописать | одно предложение до 180 знаков с подлежащим, ни одного числа, которого нет в запросе; каждое утверждение помечено находкой «Утверждение дописано сервисом» | колода только из утверждений запроса |
| `outline_planner` | 3 | текст задачи | факты | каждый факт на одном слайде, число слайдов, заголовок без чисел не из фактов | план по порядку фактов |
| `slide_writer` | 2 | текст задачи, по слайду | факты слайда | числа не меняются, до 15 слов | текст факта как есть |
| `chart_planner` | 3 | текст задачи | слайды с числами | значения графика — числа фактов, ключевое число — отрывок факта | факты текстом |
| `title_fitter` | 1 | текст задачи, после первой компоновки | заголовки, которые шаблон ставит ниже 85 % собственного кегля, бюджет знаков рамок | в бюджете, числа только из фактов слайда | заголовок остаётся |
| `speaker_notes` | 1 | каждая колода, один вызов | факты слайдов, аудитория, длительность | те же слайды, числа только из фактов своего слайда, укладывается во время | текст из фактов слайда |
| `speaker_notes_sources` | 1 | вместо `speaker_notes`, когда есть контент-пакет | то же и абзацы-источники пакета | то же | факты и абзацы-источники |
| `context_auditor` | 1 | каждая колода, по слайду | текст слайда и цитаты источника | ответ на все вопросы валидации контента, причина у «нет» | вопросы не заданы, слайд помечен на странице |
| `image_auditor` | 1 | по вариантам, слайды с картинками | текст слайда и картинки | ответ на каждую картинку | вопрос 6 не задан |
| `title_writer` | 1 | исправление «заголовок — вывод» по выбору пользователя | слайд и замечание | другой заголовок, числа из пунктов | исправление не применяется |
| `icon_tagger` | 1 | образец с местами под пиктограммы, пачки по 24 картинки | картинки образца | ответ на каждую картинку | пиктограммы образца остаются |
| `icon_picker` | 1 | колода на таком образце | пункты слайдов и смыслы пиктограмм | всем пунктам слайда или никому, только предложенные, без повторов | слайд без выбранных пиктограмм |
| `scene_marker` | 1 | разбор нового образца, один вызов на шаблон; ответ хранится | 6–10 слайдов-образцов, нарисованных программой в Chromium, и описание того, что не нарисовано | ответ принимается только в полях, которые подтверждают файл шаблона и пиксели картинок | разметки нет, колода строится по разбору файла |

## Что не является моделью

Разбор образца, вёрстка, проверки контрольного списка качества, экспорт PPTX, HTML и PDF — детерминированный собственный код. Chromium (Playwright) измеряет отрисованный текст и печатает PDF; это браузер, а не модель. PDF из контент-пакета читает pdf.js (`pdfjs-dist` 5.6.205, Apache-2.0) — разборщик текстового слоя, тоже не модель.

## Системные требования

- **Модель** вызывается через API: своей видеокарты сервису не нужно. Собственное развёртывание Qwen3.8-27B не выполнялось и не измерялось.
- **Сервер продукта** (Python 3.12, Node.js 20, Chromium) измерен на рабочем сервере: 1 процессор, 1,9 ГБ памяти без подкачки, предел контейнера 1 200 МБ. Шаблон A с текстом задачи около 9 тыс. знаков — пик памяти контейнера 870 МиБ, от нажатия до трёх вариантов 174,72 с. Шаблон 34,2 МБ с картинками макетов по 4,8 МБ на этом сервере не разобран — процесс убит по памяти: для тяжёлых шаблонов нужно больше памяти.
- **Диск:** шрифты-замены — 7,6 МБ в образе; полный набор Google Fonts без китайских, японских и корейских — около 859 МБ в отдельном томе.

## Генерация изображений

Не реализована. Третий вариант вёрстки ставит на слайды только картинки самого шаблона. Кандидаты с открытыми весами для следующего этапа — Qwen-Image (20B), FLUX.1 schnell (12B), FLUX.2 klein 4B, все Apache 2.0 (по карточкам на 21.09.2026; перед использованием перепроверить) — это план, не измерение.
