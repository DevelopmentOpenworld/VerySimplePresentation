# VerySimplePresentation: архитектура

Пайплайн и границы слоёв: парсинг, генерация, вёрстка, аудит, экспорт. Документ описывает код репозитория (`packages/core/vsp_core/`, `apps/generator/`) по состоянию на 29.09.2026, поздний вечер. Модели и агенты — [MODELS](MODELS.md), проверки — [AUDIT](AUDIT.md), три варианта — [VARIANT_AXIS](VARIANT_AXIS.md).

## Слои и модули

| Слой | Модули (`packages/core/vsp_core/`, `apps/generator/`) | Вход → выход |
|---|---|---|
| Парсинг | `materials.py`, `opc.py`, `importer.py`, `reference.py`, `typography.py`, `patterns.py`, `roles.py`, `sample_clone.py`, `icons.py`, `png.py`, `fonts.py`, `font_assets.py`, `font_catalog.py`, `mtx.py`, `scenes.py` | PPTX образца и материалы пакета → описание образца (`style.json`: макеты, плейсхолдеры, шкала кеглей, палитра, шрифты, композиции, карточки, иллюстрации, пиктограммы) и абзацы материалов с местом в источнике |
| Генерация | `llm.py`, `planner.py`, `charts.py`, `icons.py`, `titles.py`, `notes.py` | текст задачи и материалы → структурированный бриф (`vsp.brief/1`): факты, план слайдов, заголовки-выводы, графики, ключевые числа, шаги, пиктограммы, текст выступления |
| Вёрстка | `model.py`, `composer.py`, `placement.py`, `diversity.py`, `style_compatibility.py` | бриф и описание образца → три документа (`vsp.document/2`), по одному на вариант |
| Аудит | `quality.py` + `quality.js` (Chromium), `audit.py` + `audit/checks.json`, `context.py`, `fixers.py`, `pdf.py` | документы и готовые файлы → находки с серьёзностью и исправителями; выбранные исправления → новая ревизия |
| Экспорт | `carrier_export.py`, `exporter.py`, `charts.py`, `pdf.py` + `pdf_worker.mjs` | документ → `deck.pptx` на самом образце, `deck.html`, `deck.pdf` |
| Конвейер и сервис | `pipeline.py`, `progress.py`, `server.py`, `index.html`, `app.js`, `renderer.js`, `progress.js`, `manage.py` | порядок шагов, ревизии, `run.json`; страница и API |

Слои обмениваются только данными в файлах запуска (`style.json`, бриф, документы, `audit.json`, `run.json`), поэтому каждый можно проверить и заменить отдельно; модель вызывается только из слоя генерации и из контекстуального аудита, всегда через `llm.py` с проверкой ответа и запасным путём.

## Принципы

1. **Собственная модель документа** (`vsp.document/2`, координаты в CSS-пикселях) — источник истины для предпросмотра, аудита, правок и экспорта. PPTX — внешний формат, а не внутреннее представление.
2. **Экспорт на самом образце** («носитель»): мастера, макеты, темы и встроенные шрифты образца переходят в результат байт в байт, его слайды заменяются нашими, заголовки и тексты встают в плейсхолдеры его макетов, карточки слайдов-образцов клонируются целиком.
3. **Только собственный код и стандартная библиотека Python** для пакета PPTX, графиков, PNG, клиента моделей; внешняя зависимость — Chromium (Playwright) для обязательной проверки отрисовки и печати PDF (сервис должен работать на сервере без офисного пакета и дорабатываться собственным кодом); с 27.09 — pdf.js (Mozilla, Apache-2.0) для чтения PDF из контент-пакета.
4. **Факты неизменны.** Текст и числа фактов брифа не меняются ни вёрсткой, ни исправителями; изменённый факт останавливает выдачу.
5. **Каждый вызов модели проверяется** детерминированно и имеет запасной путь без модели; все вызовы — в `run.json`.

## Поток одного запуска (`pipeline.generate`)

Состояние на 29.09.2026 (поздний вечер), по коду `pipeline.generate`. В скобках после номера — имя шага, которое страница показывает в ходе работы (`progress.py`); шаг, которого в запуске нет, на странице не появляется.

1. Проверка запечатанного состава (`verify_release`): SHA-256 каждого файла продукта, промптов, схем и профилей совпадает с `profiles/mvp/release.json`.
2. (`package`, если приложен контент-пакет) Чтение материалов (`materials.read_package`): абзацы с местом в источнике, шрифты пакета.
3. (`content`, если задача задана текстом) Свободный бриф → структурированный (`planner.structure`): `brief_analyst` выделяет утверждения, `content_writer` дописывает недостающие, если запрос короткий (помечены как дописанные сервисом), `outline_planner` строит план, `slide_writer` пишет пункты; графики и ключевые числа — `chart_planner`.
4. (`template`) Разбор образца (`read_style`): инвентарь, композиции, карточки, иллюстрации, пиктограммы; шрифты — встроенные, офлайн-набор или шрифты сервера (`resolve_fonts`).
5. (`scenes`, при экспорте на образце) Разметка сцен образца (`scenes.mark`, агент `scene_marker`); подготовленный шаблон читает сохранённую разметку, без модели разметка пуста и колода строится как прежде.
6. (`icons`) Пиктограммы (`icons.choose`): разметка каталога образца и выбор к фактам — только если у образца есть места под пиктограммы.
7. (`layout`) Вёрстка трёх вариантов (`build_documents`) в порядке сборки `variants` (список, блоки, колонки: третий вариант выбирает композиции с картинками после двух других), затем выдача в порядке `variant_order` (`pipeline.issue_order`): колонки, блоки образца, иллюстрации образца; предварительный аудит (изменённый факт — остановка).
8. (`titles`, текст задачи и живая модель) Заголовки, которые шаблон ставит заметно мельче собственного кегля, переписываются под рамку (`titles.fit_titles`, агент `title_fitter`), варианты собираются заново.
9. (`notes` параллельно с `meaning`) Текст к каждому слайду (`notes.write_notes`, агент `speaker_notes` или `speaker_notes_sources` при пакете) — один вызов на бриф, текст ложится в заметки слайдов PPTX и в HTML. Контекстуальный аудит содержания (`context.review`), один раз на бриф: варианты делят факты и заголовки.
10. (`render`) Проверка отрисовки в Chromium с исправлениями геометрии и повторной проверкой с нуля; различие вариантов.
11. (`pictures`) Вопрос 6 контекстуального аудита по картинкам каждого варианта (`context.review_images`).
12. (`export`) Ревизия `r0` каждого варианта: аудит по контрольному списку качества, экспорт PPTX на образце с самопроверкой, HTML, находки.
13. (`pdf`) PDF всех вариантов одной сессией Chromium и его проверка.
14. `run.json`: состав, версии и хеши промптов каждого вызова, поставщик и производитель ответа, запасные пути, время по шагам.

Правка пользователя (`revise`) и выбранное исправление находки (`fix`) создают новую ревизию того же варианта и проходят проверку отрисовки, аудит, экспорт и PDF заново.

## Ход работы на странице

Страница показывает разбор образца, генерацию и исправление находок в тот момент, когда они идут. Данные — только измеренные:

- событие записывает код, который делает работу: конвейер — начало и конец каждого шага с секундами и итогом шага (`pipeline.py`, `progress.py`), клиент модели — отправку каждого запроса и приход ответа с его временем (`llm.py`);
- план работы содержит только шаги этого запуска: шаг, которого в запуске нет, на странице не появляется;
- страница спрашивает `POST /api/progress` о событиях после последнего известного ей; ответ ждёт следующего события, поэтому шаг загорается, когда сервер его начал (`server.py`, `progress.js`);
- отправка образца и получение результата показаны по байтам браузера; секундомер идёт от нажатия кнопки по часам устройства;
- ни один индикатор не движется по таймеру или по ожидаемой длительности; наблюдение не меняет результат запуска (проверено автотестом разработки).

События живут в памяти процесса сервера; запись запуска — `run.json`.

## Версии и откат

`apps/generator/manage.py seal` хеширует файлы продукта, промпты, схемы, профили и офлайн-шрифты и регистрирует состав `structured-mvp-<id>`; `activate <id>` возвращает зарегистрированный состав из коммита, где он запечатан, с проверкой SHA-256 каждого файла. `GET /api/versions` отдаёт состав, агентов с версиями и хешами и, по каждому запуску, какие версии ответили; те же хеши пишет каждый вызов в `run.json`. Страница этих сведений не показывает.

## Границы

- Разбор образца ограничен: сложные заливки, группы с текстом, SmartArt, EMF-декор предпросмотр рисует приближённо или помечает; PowerPoint рисует их сам, потому что экспорт идёт на образце.
- Проверка в PowerPoint — инструмент разработчика (`scripts/powerpoint_check.ps1`, `powerpoint_text_fit.ps1`), а не зависимость продукта.
- Встроенные шрифты (EOT, сжатие MicroType Express) распаковывает собственный декодер `mtx.py` на любой платформе ([FONTS](FONTS.md)); урезанный встроенный шрифт не содержит знаков, которых не было в исходной презентации (находка `SUBSET_FONT_MISSING_GLYPHS`).
